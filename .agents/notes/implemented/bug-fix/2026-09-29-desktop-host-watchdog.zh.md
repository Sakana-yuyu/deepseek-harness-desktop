# Agent Note：桌面壳用看门狗重启保活宿主

Status: implemented

[English](2026-09-29-desktop-host-watchdog.md) | 中文

## 问题

桌面壳只在启动时生成一次 `dsh web`，此后不再过问。宿主进程在壳运行期间消失——系统休眠后 WSL 虚拟机被回收、Node 崩溃——页面就会对着一个已死的回环源永远重试。用户看到智能体"离线"、无限重连，只能退出整个应用重启。

## 决策

- 看门狗任务在启动完成后开启。每 15 秒向宿主回环源发一次不带凭据的 GET 探测；任何响应（包括 401 认证墙）都证明监听存活。连续 3 次失败——约 45 秒的沉默——判定宿主已死。
- 判死后，看门狗停止死掉的宿主句柄，按启动时记录的同一条路径重新生成（Windows Node 运行时走 `spawn_web_host`，WSL 走 `spawn_wsl_web_host`），优先复用页面仍指向的端口；端口空闲时页面自身的重连循环无需导航即可恢复。
- 若重生后的宿主换了端口，壳把内容 WebView 导航到新的认证地址（`dsh web` 的一次性令牌行）。令牌交换会铸造会话 cookie，页面无需用户操作即可回到应用内。
- 重生的 URL 和宿主句柄会替换受管 `DesktopRuntime` 字段，因此托盘、插件命令与退出回收始终作用于存活的宿主代。
- 每次中断只提示一次 toast，而不是每个探测周期提示一次。探测失败绝不会重启壳本身。

## 备选方案

- 改为监视子进程句柄。否决：进程存活不等于服务存活——挂死的 Node 进程会漏判，且 WSL 路径只暴露 `wsl.exe` 桩 pid；HTTP 探测直接度量页面所依赖的真实契约。
- 宿主死亡时重启整个壳。否决：这会摧毁进行中的智能体工作，也违背用户依赖的"关闭最小化"偏好；页面设计上本就能在连接重置后重新拉取。
- 给被服务的客户端打补丁，在恢复可见时刷新页面。否决：被服务的 Web 应用是上游代码；壳侧注入 WebSocket 包装或强制刷新会与客户端自身的恢复循环打架，也无法在新源上完成认证。Rust 层拥有宿主生命周期。

## 后果

- 后端中断无需用户操作即可自愈：UI 在同端口重连，或导航后落在新的认证地址上。
- 宿主无法启动时（树损坏、端口被占），看门狗会在 boot.log 里逐周期记录重生失败并保持壳可用于其他工作；看门狗不会因重生失败退出。
- `DesktopRuntime.host` 与 `web_url` 现在位于读写锁之后；启动后只有看门狗会写入。
